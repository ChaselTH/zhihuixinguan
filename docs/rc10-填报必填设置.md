# rc.10：黄色填报列必填设置

2026-09-18，用户授权当前维护人开发、合入 main 并交付 U 盘。版本 `0.3.0-rc.10`，数据库 schema 8。保留 rc.9 功能，不启用云端 CI，不清理真实数据，不重启用户当前服务。

## 使用与完成口径

分行管理员从首页“机构数据与填报进度 → 填报必填设置”，或清单明细同名按钮进入。三个清单分别设置，每个原模板黄色填报字段可以选择“是 · 必填／否 · 选填”，一个按钮保存当前清单。其他角色可查看规则，不能更改。不会新增业务列、修改模板原表头或扩大填报权限。

- 每类清单一套规则，对全部支行、历史及未来所有期次生效，不按管理员个人保存。
- 默认全部选填：维持原规则，任意黄色格非空即完成；源字段有值不能视为填报完成。
- 指定必填列：所有必填列非空才算该行正式完成，选填列留空不影响。只有空白字符不算内容；数值 `0` 和选项“否”均算已填。
- 缺少必填项仍可保存、差异预览、提交、复核批准和直接确认，甚至可清空已有内容。操作员仍须复核后才能进入正式数据。未修改任何内容仍沿用原“无差异”处理，不制造虚假修改单。
- 必填未齐时显示缺项数量和字段提示，不计完成；未设置期限／尚未到期保持未完成白底，到期后未完成按原规则标红，黄色填写格保持原色。补齐并正式生效后恢复已完成浅绿色。
- 首页未完成数、机构三项进度、总进度、支行页、明细筛选、超期提醒、筛选导出和进度导出共用同一口径。草稿、待复核不会提前提高完成率。
- 改规则不清空已填值，不修改正式业务版本或冻结的提交快照。已打开的页面刷新后按最新规则显示；之前已完成的历史行可能因新增必填项重新变为未完成。

## 公共接口

`PlatformStore.completionRules()` 返回实际持久化服务：

```java
Map<String, CompletionRules.Setting> visible(ActorContext actor);
CompletionRules.Setting save(ActorContext actor, String dataset,
    Set<String> requiredFields, long revision);
// Setting(String dataset, Set<String> requiredFields, long revision)
// Setting.complete(List<String> values)

var rules = store.completionRules();
var before = rules.visible(divisionAdmin).get("multi");
rules.save(divisionAdmin, "multi", Set.of("feedback", "default_risk"), before.revision());
```

只有真实有效的 `DIVISION_ADMIN` 能保存；不是页面隐藏按钮代替后端授权。`visible` 需有效身份，返回三个清单的不可变设置；未设置时 `requiredFields=[]`、`revision=0`。字段使用 DatasetSchema 的稳定 key，只接受对应清单的 editable 字段，拒绝源字段及未知字段。

配置变更与 `COMPLETION_RULE_SET` 公共审计同一事务；同值保存无新增版本和审计。审计在分行域记录字段名和必填前后状态，不记录客户数据；沿用既有审计权限。旧版本保存抛 `ConcurrentModificationException`，无效字段／参数抛 `IllegalArgumentException`，越权或失效身份抛 `SecurityException`；分别映射 HTTP 409／400／403。

GET `/completion-rules?dataset=multi|negative|cross`；POST `/completion-rules/save` 包含 `csrf`、`dataset`、`revision` 和本表每个黄色列的 `required_<key>=true|false`。缺字段、非法布尔值或伪造非黄色字段均拒绝，避免缺参数导致误清空。成功重定向并提示保存。入口复用 Main 登录、首次改密、安全确认和 CSRF 门槛。

显示与导出通过 `DataStore.dashboard` 获取同一锁内的正式行、当前设置和截止日期；每行携带对应 requiredFields，使用 `RowRef.complete()`，而不是无配置的旧完成方法。无数据月份也显示正确的当前表头标记。无参数 `DatasetSchema.complete(values)`／`BusinessRecord.complete()` 只供默认规则或脱离库的测试数据使用；有正式数据上下文必须传入规则。

## 数据迁移与离线交付

仅新增 `V008__completion_rules.sql`，包含 dataset、required_fields、revision、updated_by、updated_at。V001～V007 内容及校验和不变。V7 升级初始空规则保留原完成率、账号、记录、草稿、待复核、审计和截止日期，不运行自动清理。

新装／升级沿用离线安装器、迁移暂存副本验证及完整旧版备份。schema 8 不可交由 rc.9 或更旧程序打开；回退必须使用升级前完整备份，先保全升级后的新内容和密钥。私人包不包含开发电脑业务库，不得公开上传。包内 SOURCE_COMMIT 记录准确源码 SHA；旧包保留。

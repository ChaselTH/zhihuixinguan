# 智慧信管 rc.12：通知定向与复核界面调整

2026-09-22，用户直接授权当前维护人实现以下调整，提交 GitHub 并制作离线包放 U 盘。版本 `0.3.0-rc.12`，数据库 schema 仍为 10，无新增迁移，不启用云端 CI，不重启用户现有服务。

## 需求与实现

1. 通知按机构和人员分开。操作员只看到本人提交行及被退回的通知；复核员只看到本人复核过以及之后被退回的通知。实现上，分行退回时只通知该行上次支行复核通过的具体复核员，终审重开只通知原提交人和经手复核员，不再向全支行广播。首次操作员提交仍通知本支行全部复核员以便接管。
2. 分行退回改走支行复核。分行管理员退回行后，行阶段回到 `BRANCH_REVIEW`，提交单回到待支行复核；复核员可“退回”给操作员重改，也可按原有“本人修改”路径自行修改后重新送分行。导入候选和操作员提交走该路径，支行直接修改仍退回原提交人。
3. 待复核置顶。首页与清单中 `BRANCH_REVIEW`／`DIVISION_REVIEW` 的行优先排在表的最上面，同组内保持原来源顺序。
4. 复核入口收敛。能复核的人（支行复核员、分行管理员）在清单里只保留一个“去复核”，不再同时显示“查看提交回执”；不能复核的角色保留提交回执入口，保证每行只有一个流程链接。
5. 复核界面简化。`/workflow/submission` 改成和填报一样的整行表格，第一列“操作”含“复核通过”和“退回”；退回通过 `workflowRejectReason` 弹窗输入原因后提交。多行单据保留紧凑的整单复核通过／整单退回入口，便于批量处理并保持原有整单事务语义。
6. 行历史入口。三个清单详情第一列对复核员、支行管理员和分行管理员新增“查看历史修改记录”，跳转 `/workflow/record-history?record=`，展示该行全部 `workflow_item_events`（填报、复核、退回、发布）以及相关提交单，含操作人姓名、角色、原因和单据链接。
7. 删除“历史正式数据”标签，登录数据安全提示改为正式的保密、最小授权、禁止外传、操作留痕和离岗锁屏文案。

## 涉及文件

- `src/platform/WorkflowEngine.java`：分行退回路由、按人通知、行级事件读取。
- `src/platform/WorkflowContracts.java`：新增只读的 `ItemEvent` 与 `recordEvents`。
- `src/workflow/WorkflowPages.java`、`src/workflow/WorkflowRoutes.java`：简化复核表格、行历史页与路由。
- `src/risk/BusinessRowPresentation.java`、`src/DashboardData.java`：复核入口收敛、待复核置顶、历史入口。
- `src/identity/AccessPages.java`：数据安全提示。
- `web/assets/workflow.js`、`workflow.css`、`foundation.css`：退回弹窗脚本与样式。

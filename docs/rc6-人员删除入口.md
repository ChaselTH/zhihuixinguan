# rc.6：人员管理删除按钮

版本 `0.3.0-rc.6`，schema 6，无新迁移。

- 人员管理每行操作栏为有权管理且正常启用的账号提供红色“删除人员”按钮。
- 点击后显示姓名、统一认证号、角色、所属机构及影响说明；只有点击“确认删除（停用账号）”才提交。取消或仅访问 GET 页面不会停用账号。
- 复用原 `/people/disable` 服务端处理：校验 CSRF、账号版本及管理权限，停用与 `USER_DISABLE` 审计一起写入。旧会话失效；并发修改或重复确认不会覆盖新版本。
- 超管可管理下级；分行管理员不能删除分行同级；支行管理员只管理本支行操作员／复核员。本人和超级管理员不能被删除，普通操作员／复核员无此权限。
- 删除是逻辑停用：人员保留在列表并显示“已停用”，不重复显示删除按钮；认证号仍占用，历史填报、审批与操作记录保留。可通过原修改页面恢复账号状态。
- 原待办责任检查不变，有未交接职责时拒绝停用。原修改页面底部的停用入口仍兼容。
- 使用普通链接和服务端表单，不依赖 JavaScript 弹窗；实际旧 IE 仍需现场验证。

新增 `PeopleDeleteHttpTest`，在隔离合成环境通过真实 Main HTTP 验证入口、确认目标、HTML 转义、五角色范围、跨支行／同级拒绝、CSRF、显式确认、版本冲突、原会话撤销、公共审计和恢复。现有最后管理员待办责任保护回归一起执行。不操作开发电脑上的任何真实用户。

本轮更新源码及本地服务，不重做 U 盘安装包；上次交付的 rc.5 包不含本按钮。发布前仍执行完整离线构建测试与安装模拟，不使用 GitHub CI。

2026-09-18 本地验证：`node tools/build.mjs --test --offline` 全部通过（新增删除 HTTP 31 项；综合 HTTP 270 项）；`node tests/install-smoke.mjs` 通过。用实际渲染页面及虚构人员只读预览核对列表红色按钮和确认页，未连接真实账号库。浏览器检查不代表旧 IE／麒麟实机验收。

# rc.4：反馈截止日期与超期提醒

版本 `0.3.0-rc.4`，数据库 schema 6。仅本地验证，不启用 GitHub CI。

## 操作方式

1. 超级管理员或分行管理员登录，在首页“本期反馈时间”点击“设置反馈截止日期”。
2. 选择月／季／年／区间，在各清单的来源期次行填写 `YYYY-MM-DD`，点击保存。
3. 多重预警、负面闭环、交叉违约分别配置；同一清单同一期对所有支行统一生效。可修改，也可点“取消截止日期”。支行只能查看自己涉及的期次，不能设置。
4. 首页显示当前范围最近 9 个清单期次及剩余时间，其余进入全部期次查看。点击未完成／超期数量进入该清单该期明细；完整清单增加“超期反馈”筛选，导出沿用同一范围。

只为已经导入、存在正式记录的来源期次提供设置。多重预警与负面闭环使用原来源期次，交叉违约继续按首次违约时间形成的月度期次；本功能不重新归档数据，也不更改模板。

## 判定规则

- 固定使用北京时间（Asia/Shanghai），截止日当天结束前有效；次日 00:00 起仍正式未完成才算“超期反馈”。
- 沿用任意一个可填报单元格有内容即正式完成的规则；操作员草稿、待复核内容不计。超期后仍可填写、提交、复核。
- 正式完成为浅绿色；未完成未超期为白色；超期未完成为浅红色。黄色填报列始终保留原色。
- 未设置日期不判超期。延后／提前／取消立即按新日期计算；完成后不再显示当前超期，不将其另行标记为“曾超期”。
- 页面显示剩余天／小时，当天显示小时／分钟；超期天数按北京时间的日历日期差计算。页面刷新更新提醒；没有后台定时发消息，也不依赖客户端时钟。
- 设置不改正式业务记录、完成率、工作流版本或提交快照；同一期重新导入仍保留设置。升级不会自动设置任何日期或删除数据。

## 服务契约

- `PlatformStore.deadlines().visible(actor)` 返回 `Map<FeedbackDeadlines.Key, FeedbackDeadlines.Setting>`，只含授权机构存在正式记录的清单期次。
- `save(actor, dataset, period, date, revision)`：仅超级／分行管理员；严格有效日期，空字符串为取消。首次 revision 为 0，之后使用返回版本。取消保留版本，避免旧页面覆盖新设置。
- `GET /deadlines`：沿用时间范围参数及支行隔离。
- `POST /deadlines/save`：要求身份有效、完成登录安全确认、CSRF；字段为 `dataset`、`period`、`revision`、`action=save|clear`、`dueDate` 和时间范围。
- 页面保存日期为空报错；取消必须显式提交 `clear`。无效日期或不存在期次返回 400，越权／CSRF 返回 403，旧版本冲突返回 409。
- `completion=overdue` 和可选精确 `period` 应用于列表、分页和授权 Excel 导出；日期设置是独立配置，不改变原 Excel 表头。
- 配置更新和 `FEEDBACK_DEADLINE_SET` 审计在同一事务内，审计记录前后日期和期次。审计沿用公共权限；支行不查看分行级配置操作记录。

## 迁移与恢复

新增 `V006__feedback_deadlines.sql`，主键 `(dataset, period_key)`，记录截止日期、乐观版本、修改人和时间；V001～V005 原文件不改。升级前停止旧服务并备份完整数据库及密钥；安装器仍先在副本上预检迁移。schema 6 不能交给 rc.3 或更早程序运行；恢复旧备份会丢失备份后的变化，不能直接覆盖回退。

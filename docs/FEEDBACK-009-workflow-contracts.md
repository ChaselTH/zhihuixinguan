# FEEDBACK-009 两级审批接口补充

本文件记录 PR #12 及合并前修复分支的当前契约；实现为 `WorkflowContracts`、`WorkflowEngine`，任务授权仍以独立人工交接为准。产品版本保持 `0.3.0-rc.10`，修复待维护人审查。

## 行状态、发布与责任

- 操作员：私人草稿 → `BRANCH_REVIEW` → `DIVISION_REVIEW` → `PUBLISHED`。支行复核通过只推进任务；分行终审才写正式值、版本和完成状态。
- 支行管理员／复核员本人修改：差异确认后直接送 `DIVISION_REVIEW`；没有本人支行复核。分行管理员本人修改仍以差异确认作为终审发布。超管业务只读。
- `Mode.IMPORT` 是上传的候选内容，上传人标识来源责任。黄色候选不提前发布；有效支行复核员必须逐行确认，才允许分行终审。允许唯一分行管理员终审自己的上传候选，但服务端必须验证该行有独立 `REVIEWER` 的 `BRANCH_APPROVED` 事件。普通 `REVIEW` / `DIRECT` 不放宽本人审批限制。
- `State.PARTIAL` 是单据汇总；每行以 `rowStages` 和当前记录活动任务为准。所选多行同一事务成功或失败；禁止跨单活动任务推进。`approveRows` / `rejectRows` 不影响未选择行。
- 两级在途记录均阻断按月删除和导入覆盖。预览计数和确认时复验都不可省略，旧预览不能绕过并发新增任务。

## 可见内容与回执

`submission`、`submissions`、`recordHistory`、确认／审批的重试结果在服务层逐行裁剪：支行仅有本机构范围，当前 `DIVISION_REVIEW` 或已完成正式行不下发 `SnapshotRow`。`rowStages` 保留本机构流程回执；其条数可能大于 `rows`，页面不得从回执自行重建完整内容。全域角色按原授权读取完整快照。

判断依据是当前记录状态和当前完成规则，不是某个旧提交单的历史状态。终审仍缺必填项的正式行恢复支行可见范围。旧草稿、旧预览、幂等重试、混合行单据均须遵守此边界；不可见版本冲突不附带字段快照。已提交草稿不可编辑，只有当前退回行可恢复。

通知正文只含流程摘要，链接再次执行当前权限检查。业务列表、搜索、筛选、导出沿用统一待处理范围；统计保留整体进度。按任务原有约定保留授权操作审计历史，继续执行机构域、超管事件隔离和私人草稿保密；不通过新接口重建已清理审计。`DRAFT_SAVE` 和 `DRAFT_RESTORE_RETURNED` 均不进入公共审计查询。

## 退回、原值重提和接续

以下方法省略首个 `ActorContext actor`；会话身份、版本、事务和请求编号规则与公共服务一致。

| 方法 | 当前约束 |
| --- | --- |
| `reopenCompleted(recordId, expectedVersion, reason, requestId)` | 仅分行管理员，允许 `PUBLISHED` 和 `LEGACY_PUBLISHED` 的完成行。保留正式值／版本，当前阶段改为 `RETURNED`；有来源单时同步对应行和整单汇总。每轮重开独立通知，同请求重试一次。 |
| `previewReturned(recordId, expectedVersion)` | 仅当前退回行。冻结原正式值、正式版本和前单关联，产生没有字段变化的明确重提预览。操作员仍走两级，支行直接修改角色仍送终审。 |
| `restoreReturned(submissionId, recordIds, requestId)` | 操作员将本机构当前退回行的已提交快照复制成自己的新私人草稿。逐行核验当前活动前单，支持 `PARTIAL`；原作者停用不阻断接续，不复制其私人草稿。 |
| `editableDraft(id)` / `drafts(dataset, offset, limit)` | 本人草稿；已提交版本只有仍活动退回的行可恢复，按当前正式基线供编辑。其余待审／已发布行不会一并恢复；软删行跳过。原始存储快照不因读取被重写。 |
| `saveDraft(..., priorSubmissionId, requestId)` | 前单关联须同机构、同表种且所选每行当前确为该前单退回；不再要求整单 `RETURNED` 或同原作者。普通无变化保存仍是空差异，不能伪造修改。 |

原值重提通过普通 HTML 的勾选确认 → 服务端预览 → 正式确认完成。发布没有字段变化时不增加正式行版本，但保留新提交单、两级处理事件及前单链。回到修改页可编辑原值，或重新进入原值核对入口；不把普通无变化保存隐式解释为重提。

## 工作簿和迁移

自动识别先检查真实业务表头，再识别完整的已知说明页；名称含“模板／说明”不影响有效数据。仅完整匹配本版或旧版生成的单列说明文本且没有额外数据的页可忽略。未知非空页报错。单表、三子表、同类多 sheet 仍用一个上传入口，月份以用户选择为准，来源日期保留。

本轮用户确认 V009/V010 从未被实际应用，因此修正未发布 V009 并以 `LegacyWorkflowMigration` 初始化当前行状态。V001～V008 和 V010 原文保持不变：待审优先；历史决定按时间、批准事实及正式版本判定，旧退回不覆盖之后批准。schema 8 多人同一行待审保留全部原快照／占用记录，先明确退回重复任务，再推进剩余任务。迁移只初始化新增投影，不改旧正式值、历史版本、审计、草稿和审批链。

新装和真实 schema 8 升级均走正常顺序迁移。已经应用原 PR V009 的测试库会被 checksum 校验明确拒绝；应保全该库，并在隔离目录从验证过的 schema 8 升级前备份重做。不得篡改迁移校验记录、清库或用旧程序强开 schema 10；没有备份时须另行设计维护人批准的兼容迁移。

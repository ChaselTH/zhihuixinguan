## 2. 页面与数据口径

- 首页多重预警、负面闭环各只预览前 8 条正式未完成数据，“查看全部”进入完整清单；没有未完成时区分“全部已完成”与“无记录”。趋势和行业图表不恢复。
- 三张完整清单支持全部／已完成／未完成；时间、机构、搜索、完成状态共用筛选，翻页及切换时间保留其他条件，导出全部匹配记录，不限当前 50 条页面。
- 任意黄色填报字段非空即正式完成，`0`、`否`亦算；清空最后一项即未完成。浅绿色为已完成，白色为未完成，黄色填报格不被行颜色覆盖。完成率包含三类正式记录；无数据支行显示灰色横线，不冒充已完成。
- 私人草稿只显示给本人；清单中仍显示正式值，不公开草稿正文。待复核、退回、最近直接生效／通过作为独立流程提示，不改变正式完成统计或导出。
- 多个操作员可对同一记录有不同待复核单；操作员优先看到本人单据，其他授权人员可从该记录追溯查看全部提交。已提交／已批准的草稿版本不显示成未提交草稿；退回的仍可恢复。正式值后来改变不会“复活”已批准草稿。
- 行级按钮进入 B1 精确记录编辑、本人草稿恢复、待审详情或追溯。超级管理员只读；其他角色继续执行既有提交权限和服务端差异确认。分行跨机构清单不可整页提交，先选一家支行或使用单条入口；单支行保持页顶统一保存／预览按钮。
- 记录追溯沿用公共 `recordHistory`、提交详情及 `/audit`，不新建审计表或开放草稿历史给他人。支行角色始终只有本支行。
- 导航“行内数据”进入独立概览：已配置的交叉违约可筛选、填写和授权导出；其他行内报表显示“待配置”，不伪造表头、不开放无模板上传导出。
- 业务页面沿用现有宽屏布局；长表格只在自身容器横向滚动，长反馈列加宽并换行。表单、选择和跳转由服务端完成，不引入联网资源或现代前端框架。

反馈截止字段、正式安全文案、其他行内模板尚未提供；本轮不推定超时、不做无风险按钮。

## 3. 接口与文件边界

| 接口 | 说明 |
| --- | --- |
| `GET /`、`/branch?branch=武进` | 原首页及机构分表预览，新增流程提示 |
| `GET /details?dataset=multi&completion=incomplete` | 完整清单；仍接受 scope/month/year/quarter/start/end/branch/q/page |
| `GET /export?dataset=multi&completion=incomplete` | 与详情共用 BusinessFilter，仅正式值；不含流程状态或私人 Sheet |
| `GET /internal` | 固定已配置 cross，支持相同时间／机构／搜索／完成筛选 |
| `GET /records/history?id=稳定记录ID&offset=0` | 先授权 find，再分页查询公共工作流记录，25 条／页 |
| `GET /workflow/edit?...&record=稳定记录ID` | 新增可选精确定位；核验身份、表种、机构和期次，保存草稿后保留定位 |

非法完成筛选返回 400；跨支行记录／筛选返回 403；所有入口仍经过 Main 的登录、账号版本、首次改密和安全确认，写入仍用 B1 的 CSRF／事务／版本保护。`record` 只是定位提示，不是写入授权。

新增 `src/risk/BusinessFilter.java`、`BusinessWorkflowState.java`、`BusinessRowPresentation.java`、`BusinessRoutes.java`、`src/internal/InternalPages.java` 和局部 `business.css`。公共维护人同时完成 Main 注册、导航、DashboardData 筛选重载及 AuthorizedExportService 接入。B1 编辑页仅向后兼容增加 record 参数，无平台数据库／身份接口改动。

草稿和提交通过现有公共分页 API 获取，逐页读取，不只取前 100 条；元数据只为本页展示行建立。生产规模下的查询性能仍需压测，不能把虚构小数据测试当成容量证明。

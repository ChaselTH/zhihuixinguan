# A1-001：权限与公共页面交接

开发分支：`codex/v0.3-access`。版本 `0.3.0-a1.1`，数据库 schema 3。共同代码基线为 PR0.7 `c8198f70cd4dabece3ce22c21f4611de056c42d5`，A1 分支同时包含已合入 main 的 B1 派发文档（PR #3）。本文件描述 A1 实现，不授权 B2 或发布安装包。

## 已实现范围

1. 登录页增加“申请权限”；分行 / 支行使用无需 JavaScript 的切换链接，分行不显示支行选择器，支行只允许九家机构。申请仅填写姓名、统一认证号、机构，不接受自报角色或权限。
2. 分行申请由超级管理员处理；支行申请由本支行管理员处理操作员 / 复核员，需开通支行管理员时可写明原因转交分行。无支行管理员时进入分行队列。超级管理员和分行管理员可处理其管理范围内的支行申请，并接收通知，避免管理员缺位造成孤立待办。
3. 批准必须主动选择角色；服务端再次检查管理层级。审批创建账号、随机初始密码哈希、申请状态、通知、审计、幂等结果全部在同一事务中提交。退回 / 转交原因必填。
4. 新账号首次改密规则保留；超级管理员仍不强制首次改密。初始密码只在首次成功的 POST 响应中显示一次，响应禁止缓存；重复同一审批请求不再次显示密码。如响应丢失，管理员应在人员管理中重置，不能找回明文。
5. 所有角色每次登录都需要确认数据安全提示；先完成强制改密，再确认安全提示。GET / POST、导出、上传均在服务端门禁之后。当前版本只有测试占位提示，正式文本待用户提供。确认记录保存用户、会话 SHA-256 摘要、提示版本和时间，不保存原始会话令牌。
6. 公共通知中心：全量 / 未读、每页 25 条、详情、个人已读、右上角未读气泡。刷新 / 页面跳转时更新数量，不依赖在线服务或现代 JS。权限申请通知可进入授权详情；工作流通知已保留，但业务审批页面链接在 B1 集成时由 A 接入。
7. 公共操作记录：机构、表类型、日期（北京时间）、操作人姓名及记录 / 请求 / 提交单编号查询；展示修改前后和工作流审计单据关联。业务记录按支行隔离，分行与超管可查看全行。账号安全记录仅管理员可见；支行管理员仅查看本人管理操作，避免向客户经理或同级人员公开身份管理详情。私人草稿内容不进入共享日志。

## 防护与错误语义

- 匿名申请使用单独的 `ZXAPPLY` HttpOnly Cookie，Path `/access/apply`；令牌 15 分钟、一次性，不能复用登录令牌或伪造表单字段。
- 每个来源 IP 十分钟最多 5 次有效 CSRF 提交；匿名令牌池与来源计数最多 10000 项，待处理认证号最多 10000 个。限流返回 429，不写入申请。共同出口的测试环境可能共用限额；生产阈值后续由 A 根据行内网络调整，不由 B 绕过。
- 已有账号、重复待办和新申请返回相同公开回执；重复申请不覆盖原姓名、机构。待办认证号在数据库唯一占用，退回后允许重新申请。已有账号应由管理员维护，不自动另开户。
- 403：身份失效、跨机构、审批越权、个人通知越权、CSRF 失效；400：输入不合法、缺少角色 / 原因、同请求编号不同内容；409：待办版本已变化；500：事务错误且整单回滚。
- 同一申请竞争审批只有一个成功；同请求重试返回 `replayed=true` 且无初始密码。另一个管理员处理完的申请不能再次审批。
- 所有表单与日志中的用户文本进行 HTML 转义；没有外部字体、CDN、联网调用，也没有客户端决定权限的逻辑。

## 公共 API（B1 原接口不变）

`PlatformStore.workflow()`、`PlatformStore.notifications()`、原 `WorkflowService` / `NotificationService` 方法与 DTO 均保持 PR0.7 签名。A1 只将工作流内部通知写入方法收敛为同包可用，以便审批事务复用，不开放 HTTP 绕过入口。

新增 `PlatformStore.access()` 返回 `AccessPlatform`：

```java
// 匿名入口只由 Main 在一次性 CSRF、请求体限额与来源限流之后调用。
store.access().apply(number, name, organization);

var requests = store.access().applications(actor, true, 0, 25);
var request = store.access().application(actor, requestId);
var result = store.access().decide(actor, request.id(), request.revision(),
    "APPROVE", Role.OPERATOR, "已核验身份", uniqueRequestId);
// result.created() 仅第一次批准成功有值；禁止日志输出 initialPassword。

var notices = store.notifications().inbox(actor, true, 0, 25);
var detail = store.access().notice(actor, noticeId);
store.notifications().markRead(actor, noticeId);

var filter = new AccessPlatform.AuditFilter("business", "WUJIN", "multi",
    submissionId, null, null);
var audit = store.access().audit(actor, filter, 0, 25);
```

所有带 ActorContext 的新增服务只接受当前真实持久化身份，不接受测试用负版本身份。方法返回的 Application、Decision、AuditEntry 字段见源码 record；查询为只读投影，不含密码哈希。不要在事务里再次调用开启事务的服务；A1 内部创建账号通过同连接 helper 实现，故障注入已验证整单回滚。

## HTTP 路由及 A/B 接入边界

| 入口 | 方法 | 门禁 / 作用 |
| --- | --- | --- |
| `/access/apply` | GET / POST | 匿名申请，POST 独立 CSRF + 限流 |
| `/access/received` | GET | 通用回执，不查询人员状态 |
| `/security`、`/security/ack` | GET / POST | 当前会话安全提示 / 确认，POST 会话 CSRF |
| `/access/requests`、`/access/request` | GET | 授权管理员申请列表 / 详情 |
| `/access/decision` | POST | 审批、退回、转交，版本 + 请求编号 + CSRF |
| `/notifications`、`/notifications/detail` | GET | 本人通知 |
| `/notifications/read` | POST | 本人已读，CSRF |
| `/audit` | GET | 授权范围公共操作记录 |

B1-001 继续按任务文档写 `WorkflowRoutes(PlatformStore,String)`，返回是否处理的 `get/post` 签名不变。B 不复制安全确认、通知中心、身份审核或审计存储。公共 Main、导航、静态资源白名单、工作流通知详情跳转及测试注册由 A 在 B1 PR 集成提交中接入。A1 代码不依赖尚不存在的 WorkflowRoutes，也不让未完成模块以 500 失败启动。

# V0.4 工作流重构验收说明

本版为 `0.4.0-rc.2` 联调候选，数据库 schema 保持 10。以下规则以当前代码和本地合成数据回归为准，不代表麒麟或 Win7 IE 实机验收。

## 角色与任务流转

| 当前环节 | 可处理人 | 操作 | 下一环节 | 正式数据 |
| --- | --- | --- | --- | --- |
| 初始未填报／正式未完成 | 本支行操作员 | 保存本人草稿／提交 | 支行复核 | 不变 |
| 支行复核 | 本支行复核员 | 通过 | 分行终审 | 不变 |
| 支行复核 | 本支行复核员 | 退回并填写原因 | 原操作员 | 不变 |
| 分行终审 | 分行管理员 | 通过 | 已发布 | 原子更新 |
| 分行终审 | 分行管理员 | 退回并填写原因 | 支行复核员 | 不变 |
| 分行退回后 | 本支行复核员 | 再退原操作员，或保存本人修订并提交 | 原操作员／分行终审 | 不变 |
| 已完成旧行重开 | 分行管理员 | 填写原因并确认 | 支行复核员 | 原正式值保留，暂不计已完成 |

旧行若无法追溯有效原操作员，仍交支行复核员；不随机分派给其他操作员。复核员可核对后通过，或修订再送分行，但不能把它退给不相关的操作员。

支行管理员只读查看本支行待处理业务和授权记录，不直接改写正式值；超级管理员可跨机构查看和管理，但不替代业务复核。操作员在提交后至退回本人或终审结束前，看不到该行的业务正文，但能在工作流查看按行实时阶段、上一处理人和当前处理人。通知为个人回执；已读状态不影响待办。

## 页面验收路径

1. 用操作员从三类清单的未完成行填报，保存草稿，刷新恢复，点击提交并确认。核对行从操作员待处理清单移除，工作流保留进度，正式统计／导出仍未完成。
2. 用支行复核员从首页待处理或工作流待办进入。核对待审行排在前面，表格第一列可单行通过或退回；退回必须填写原因，多行单据可全部通过／全部退回。
3. 退回后用原操作员检查原因和保留的上次填写内容，再保存／提交；用其他操作员确认无法读取该人的退回正文或私人草稿。
4. 支行通过后用分行管理员终审，核对终审前不更新正式值，终审后行从待办移除、完成率和导出同步更新。
5. 分行退回后确认任务先到支行复核员；复核员分别测试再退操作员和本人保存修订／提交。旧行无原操作员时测试复核员处理及再次被分行退回。
6. 从首页、完整清单、通知列表、提交记录、行历史进入下一级页面，逐级点击“返回上一页”，核对返回来源和筛选条件；在通知列表点击后核对自动已读及“全部已读”。
7. 用分行／超级管理员核对全表、支行角色跨机构拒绝、支行管理员只读、旧直接修改和“核对后原值重提”入口拒绝访问。

## 发布前仍需完成

- 在实际麒麟版本和 CPU 架构上执行离线安装、旧版数据保留升级、启动和回退演练。
- 在实际 Win7 IE 版本／文档模式下执行登录、草稿、复核、退回、通知、返回和导出操作；DOM 模拟不代替实机。
- 由行内审核登录数据安全提示示例文本，并核对正式网络传输保护、人员授权与审计留存要求。
- 以脱敏样本完成各角色人工验收；在此之前保持 `rc` 联调标识，不宣称正式投产。

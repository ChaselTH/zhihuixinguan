# rc.3 导入与风险展示调整

2026-09-17 用户授权当前维护人直接开发并提交 main。版本 0.3.0-rc.3，数据库 schema 仍为 5，不启用云端 CI；本轮不制作新的 U 盘包。

## 使用变化

- 数据更新仅选择完整三表工作簿，可多选。不再填写所属月份或补充期次。
- 多重预警、负面闭环按表内时间顺序，缺失时尝试文件名期次；交叉违约按 L 列“违约首次出现时间”分月，日期规范化为 YYYY-MM-DD，缺失或无效则整批错误。
- 预览先给完整批次的新增、重复、填写不同及两种模式预计更新数量，逐企业差异按需展开。相同来源的判定仍包括清单、机构、规范期次、全部非填报字段；不会模糊合并同名企业。
- “保留”保留旧非空填报、只补空白；“覆盖”采用上传值，空白也可清空。菜单选择不需要另行保存，不提供全部跳过，不再有两项勾选。点击确认出现包含计数和覆盖风险提示的弹窗；取消不写入，无脚本时走服务端确认页。
- 预计更新仅计重复记录中正式值实际变化的行，不包括新增；同一行多字段变化仍只算一条。预览后正式数据变化仍整批拒绝，不自动覆盖新数据；重复确认保持幂等。
- 交叉违约纳入风险预警的第三张指标卡、未完成清单和全部统计；第四张为资料补充进度。四卡均能进入对应列表／进度汇总。
- 九家支行各显示多重、负面、交叉三个完成数／总数／比例，点击进入对应清单；零记录显示“本期无记录”，不误报为未完成。
- /progress 按所选月／季度／年／自定义区间和机构汇总三类正式填报。/export/progress 一次导出各支行各清单及合计，只有超级管理员和分行管理员可使用，支行角色直接请求也返回 403。草稿和待复核不计完成。
- 行内数据仅保留待配置空状态，交叉违约不再在此重复展示。
- 业务明细默认每页 20 条，可选 10／20／50；分页链接保留时间、机构、搜索、状态和页容量，导出仍是完整筛选结果。详情／追溯／工作流明细有返回入口。
- 本地脚本为长表增加顶部原生横向滚动条，与原底部双向同步；禁用脚本时仍可底部滚动、分页和服务端提交，不使用外网库。

## 接口与兼容

新增 POST /imports/confirm-bulk 字段：csrf、token、revision、mode=preserve|overwrite、confirmed=yes。身份来自服务端会话，保留上传权限、任务本人隔离、CSRF、版本检查、幂等、原子事务。客户端不提交业务单元格替换数据。

旧 /imports/confirm 和 /imports/choices 暂保留用于旧客户端兼容；新版页面不使用保存决定或跳过。新入口传递明确整批模式，不会误用旧任务已保存的逐行选择。

ImportPlatform.Summary 新增 preserveUpdated、overwriteUpdated，两者与实际正式合并算法一致，统计覆盖完整批次而非当前明细页。

新增 BusinessFilter.pageSize，默认 20，仅接受 10、20、50；范围、机构权限仍在服务端校验。未改变操作员审批要求、管理员直接确认逻辑、黄色完成口径或数据库迁移。

历史交叉违约不会在安装时自动改月或删除。本次用户明确表示本机都是测试数据，维护人另行备份后仅清理本机交叉违约正式记录，账号及其他两类记录保留；该操作不是产品升级逻辑，私人备份／清理工具不提交。

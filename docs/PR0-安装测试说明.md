# 智慧信管 0.3.0-pr0.6 账号权限基础测试版

## 这次可以测试什么

添加和修改人员时，选择分行管理员会隐藏机构下拉，后台自动归属分行；其他角色显示所属支行，且只有本账号允许管理的支行可选。支行角色必须选择支行，不能归属“分行”；切换到分行管理员后无需手动清理之前选过的支行。

- 三个独立入口：负面闭环、多重预警、交叉违约。可上传一个对应子表文件，也可分别在三个入口上传同一个三子表文件，每次只读取对应子表。
- 自动识别新表头；提供不含示例客户的三个空白 `.xlsx` 模板。兼容可被 POI 识别的 `.et`、`.xls`、`.xlsx`，不支持加密文件。
- 可填范围依据本次用户模板固化：负面 J–L；多重 I–P、R–V；交叉 M–O。未来随意给其他列染黄不会自动扩大可编辑权限。
- 任意一个黄色填报单元格有非空内容即为完成；来源字段、空白和纯空格不算；数字 0 和“否”算有内容。“无风险”按钮暂不提供。
- 固定九支行，月／季／年／自定义月份区间；首页两张风险清单只显示未完成项，明细查看全部、黄色列填写和导出；交叉违约暂放“行内数据”。
- 新嵌入数据库、稳定记录编号、版本冲突保护、事务审计、旧数据只读迁移；导入先预览再确认。重复来源默认保留已有填写，明确确认后才可覆盖（包括清空）。

## 这次还不能当作完整功能验收

本版已接入真实持久化账号，可用不同账号测试角色菜单和本支行范围。统一认证号作为本系统账号，不代表对接了行内单点登录。统一入口 `/login`，旧 `/admin` 页面和密码专用接口停用。

首次初始化只使用应用目录的 bootstrap.local.properties 中 auth_number 和 password，不再内置固定认证号或密码。超级管理员不要求首次改密，登录后可直接添加分行管理员、支行管理员、操作员、复核员。其他人员由管理员新增时生成随机初始密码，仅展示一次，首次登录仍须修改。已有账号库在升级和重启时不重建账号、不重置密码，也不依赖该初始化文件。

修改密码页的当前账号不可编辑，当前密码仅显示固定只读掩码，不是真实密码；只需输入新密码和确认。改密使用最近 15 分钟内的登录身份，超过时限会要求重新登录后再打开改密页。不能设置与原密码相同的密码；修改成功后原有登录全部失效。

超级管理员不能上传、填写业务数据，请先创建一个分行管理员账号来测试上传。分行管理员可管理支行管理员和操作员、复核员；支行管理员只能管理本支行操作员、复核员。姓名／角色／机构／状态变化或密码重置会让该用户旧会话失效。“删除”采用停用，可恢复，不删除历史记录；不能通过界面新增、停用或降级超级管理员。

尚未开放权限申请、通知、操作员草稿、PR 式复核、正式审计查询界面和安全提示确认页。因此操作员当前只读和导出，不可直接修改正式数据；分行管理员、支行管理员、复核员可在授权范围填写。不要把本版作为正式审批投产版本。

表格没有独立反馈截止时间字段，本版不做超时标红，也不猜测截止日期。权限和复核完成前，建议仅使用脱敏测试数据。

## 安装与启动

将 U 盘中完整 `zhihui-xinguan-offline-0.3.0-pr0.6-kylin` 文件夹复制到麒麟本地磁盘。不要只复制 install.sh。PR0.6 将初始化凭据移到私有本地配置，保留 PR0.5 的机构联动、超管免首次改密和当前密码只读显示。

```bash
cd /复制位置/zhihui-xinguan-offline-0.3.0-pr0.6-kylin
bash install.sh
cd "$HOME/ZhihuiXinguan-PR0"
./start.sh
```

通用包新安装后、首次启动前，需要把应用目录的 `bootstrap.example.properties` 复制为 `bootstrap.local.properties`，在本机填写 `auth_number`（6～20 位数字）及 `password`（10～128 位），执行 `chmod 600 bootstrap.local.properties`。私人定制包若已显式带入配置，install.sh 会自动复制，无需再次填写。不要把配置或私人包上传 GitHub；更改配置不会改变已有账号密码。升级已有安装时优先保留原本地配置和账号库。

默认与旧正式版并排安装，不修改 `$HOME/ZhihuiXinguan`。启动询问端口，回车用 2874；若旧版占用，可填 2875 等未占用端口。终端显示启动与运行状态，按 Ctrl+C 等待“已停止”后再关窗口。

```bash
./start.sh status
```

访问 `http://麒麟电脑IP:所选端口/`，未登录会进入 `/login`。请填写统一认证号和密码，登录后按角色显示菜单。密码不通过通知、日志或安装说明分发。工作电脑无需安装 Java、数据库或 Node；包含 x86_64 与 aarch64 两套 Linux Java，安装自动选择。

注意：完全离线不等于网络传输加密。当前为 HTTP，只应在获准隔离内网使用，端口开放按单位要求办理；未来正式多用户部署需另行核验内网 TLS/网关及旧 IE 兼容方案。

## 以后更新 PR0 与测试旧数据迁移

更新默认 PR0 目录：先停止该目录服务，然后运行新包 `bash install.sh`，无需卸载。只有用户明确要在旧正式目录试升级时，才改用：

```bash
INSTALL_DIR="$HOME/ZhihuiXinguan" bash install.sh
```

安装器只接受带智慧信管安装标记的现有目录。先校验离线包、复制旧数据到暂存目录，再运行数据库检查与迁移；这些步骤失败不会动原目录。成功后完整旧版和旧数据保存为安装父目录内 `.zhihui-xinguan-backup-时间-编号`，不会自动删除。磁盘需至少 1 GB 可用，旧数据较大时还需留出复制与备份空间。

迁移不改写原 `data/months` 中 `.rows`／`.properties` 文件；无法映射的旧机构进入待确认区，不分给任意支行。旧多重备注、旧负面客户经理等新模板不包含的历史值保留在明细末列。旧 `auth.properties` 原文件保留但不再用于认证；首次从旧单密码版升级建立新账号库时，需要本地初始化配置。新账号库非空时，不重建管理员、不重置密码。迁移后不要再用旧程序继续写同一份旧数据文件。

如需回退，先停止新服务，保留完整新目录及数据，将备份复制到另一个明确的新目录启动核对。不要直接把旧版 JAR 覆盖到新数据库上。旧版备份不包含升级后的新增填写，应先联系维护人确认如何保留这些变更。

## 建议的验收顺序

先用超级管理员登录，应直接进入首页且能打开“人员管理”，无需首次改密。分别创建分行管理员和两家不同支行的账号，确认这些新账号仍须首次改密，当前密码框不可编辑且只需输入两次新密码。用分行管理员做以下导入测试，再登录各支行账号核对只能看本支行，且修改人员角色或停用后原会话失效。操作员目前不显示正式保存按钮。

1. 先导入三个空白模板：应提示格式通过、没有业务数据，不出现示例客户。
2. 使用脱敏表各放两行，选择对应入口上传：预览前后没有确认时正式记录数不变；确认后只增加该入口数据。
3. 多重表仅填一个黄色格并保存，应变为已完成，首页未完成清单不再显示，查看全部仍可见且来源格浅绿色。
4. 三个模块检查武进等九支行、营业部、跨月和季度范围；导出后检查列顺序、黄色标记与中文内容。
5. 再传重复记录，先试默认保留，再看差异预览，确认后才试覆盖；上传错误入口或损坏文件应报错且不改变数据。
6. 两个窗口同时编辑同一行：后保存的旧页面应提示冲突，不应覆盖先保存的值。
7. Ctrl+C 停止并重启，数据与版本号仍在；再次 install.sh 更新后仍保留数据和密码，并出现完整旧版备份。

本地 Java 自动回归与安装器模拟测试不代替麒麟实机、CPU/系统版本与 Win7 旧 IE 验收。页面使用服务端 HTML 和本地资源，不依赖现代 JS 框架；旧 IE 不支持多选文件时，可用第二个文件框或分批上传。反馈测试问题时提供系统版本、CPU 架构、IE 版本、错误文字即可，不要发送业务明细或密码。

## B1 所需数据

### 私人草稿

- 草稿 ID、所有人用户 ID、所属机构、数据集、草稿版本、更新时间。
- 每条变化使用现有 `RecordChange`：稳定记录 ID、正式记录基准版本、按 `DatasetSchema` 字段键保存的新值。
- 同一草稿只包含一个机构和一个数据集；只保存真正变化的可编辑字段。
- 草稿内容仅本人可读写；普通支行操作记录页不得展开其他人的未提交草稿。
- 保存草稿不能修改正式记录、完成率、正式更新时间、正式导出或复核待办。

### 不可变提交单

- 提交单 ID、草稿所有人、所属机构、数据集、状态、创建时间。
- 冻结的 `RecordChange` 列表及各记录基准版本；提交后不得原地修改。
- 复核人、决定时间、退回原因或批准备注；重新提交应创建新单，并可关联上一张已退回单。
- 状态至少覆盖 `SUBMITTED`、`APPROVED`、`RETURNED`、`CONFLICT`；草稿状态仍由草稿实体维护，不能把已提交快照继续当作可编辑草稿。
- 初版同一操作员、同一正式记录不得同时存在两张待复核提交单；跨数据集变化拆成不同提交单。

### 通知与收件回执

- 事件 ID、事件类型、数据所属机构、服务端时间、最小摘要和授权详情目标。
- 每位接收人单独保存回执及已读时间；未读数字只按当前账号的回执计算。
- 工作流事件至少包括操作员提交、复核批准、复核退回。提交时通知本支行全部有效复核员；决定后通知原提交人。
- 通知摘要只提供操作者、数据集、期次摘要和变更条数，不携带密码或完整敏感字段差异。
- 已读与待办状态独立：读过通知不能改变提交单状态，待复核单在批准或退回前仍留在待办列表。

### 审计追溯

- 保留事件 ID、服务器时间、操作者 ID／姓名快照／当时角色、数据所属机构、记录 ID、期次、字段旧值和新值、动作来源、提交单 ID、审批人和退回原因。
- 动作明确区分 `DRAFT_SAVE`、`SUBMIT`、`DIRECT_EDIT`、`REVIEW_APPROVED`、`REVIEW_RETURNED` 和导入类事件。
- 正式字段必须能追溯到提交人和批准人；草稿事件不得冒充已生效修改。
- 支行角色只能查询本支行审计；超级管理员和分行管理员可查询全行授权范围。系统网页不提供删除或修改审计记录的功能。

## 公共维护人需先提供的契约

以下属于 `src/platform/`、数据库迁移和通知公共模块，由 A／公共维护人实现并先合并；B 不直接修改这些独占文件。

1. 通知发布契约：显式接收事件类型、机构、最小摘要、授权目标、接收人用户 ID 和幂等请求 ID；校验接收人仍有效且属于允许范围，原子写入事件及逐人回执。
2. 通知查询契约：按当前 `ActorContext` 查询本人的通知、未读数和标记已读；不能通过客户端 userId 查询他人回执，详情跳转仍需重新鉴权。
3. 工作流持久化契约：支持私人草稿的按所有人读写、提交时冻结不可变快照、读取授权范围内提交单、退回后创建新一轮关联；不能要求 B 另开 H2 连接或建立第二套存储。
4. 审批正式写入契约：锁定并验证提交单仍为 `SUBMITTED`，复核员属于同一支行，全部记录属于提交单机构和数据集，正式记录版本与冻结基准一致，字段仍是 `DatasetSchema` 可编辑字段。
5. 审批成功必须在同一事务更新全部正式记录及版本、提交单状态、逐记录审计、批准通知和请求幂等结果；任一步失败整单回滚。重复批准返回同一个已完成结果，不再次覆盖后来数据。
6. 退回契约：只把有效待复核单转为 `RETURNED`，强制非空原因，写入审计和提交人通知，不修改任何正式记录。
7. 直接提交契约：分行管理员、支行管理员和复核员经过服务端差异确认后直接生效，同时形成可查询变更单、正式数据、审计、通知及幂等结果；超级管理员和操作员不得使用。
8. 明确、可测试的失败语义：未登录／身份版本失效、无权限、跨支行、单据状态已变化、正式记录版本冲突、重复请求内容变化、格式或字段错误分别返回可识别结果。

公共契约中不得修改已应用的 V001；如需结构变化，使用新增版本迁移并先补可重复、安全的迁移加载机制。

## B1 计划交付范围

在公共契约就绪后，B1 仅写 `src/workflow/`、工作流专用样式和工作流测试：

- 操作员保存／恢复私人草稿。
- 服务端差异预览；只预览不产生提交单、通知或正式写入。
- 确认提交后冻结快照并生成待复核单。
- 复核员待办、差异详情、批准和退回；退回原因必填。
- 分行管理员、支行管理员、复核员的直接提交差异确认。
- 版本冲突详情展示“原基准值／当前正式值／拟提交值”，要求重新核对，不自动合并。

B1 不修改 `AuthService`、身份页、公共启动入口、公共外壳、基础 CSS、`src/platform/`、数据库迁移、构建／安装脚本和版本号；需要调整时先提出公共契约请求。

## 验收案例

### 权限与隔离

1. 操作员只能保存和查看自己的草稿；同支行其他操作员不能读取，跨支行任何角色不能读取。
2. 操作员只能提交本支行正式记录；修改 URL、隐藏字段、记录 ID 或机构参数不能越权。
3. 复核员只能查看和处理本支行提交单；两位复核员都能收到待办，但只有第一位有效决定可以生效。
4. 超级管理员业务只读；分行管理员、支行管理员、复核员可直接提交；只有分行管理员保留上传权限。

### 草稿、预览与提交

5. 保存、恢复、覆盖本人草稿均不改变正式数据、正式版本、统计、首页未完成列表和导出。
6. 差异预览列出企业／记录、支行、数据集、期次、字段名、正式旧值、拟提交新值和变化条数；只打开预览不产生通知或待办。
7. 确认提交生成一次不可变快照；刷新或重复提交同一请求只得到同一个提交单。
8. 待复核期间修改新的私人草稿不能改变复核员看到的冻结快照。

### 批准、退回与并发

9. 批准在一个事务内更新全部正式行、版本、提交单、审计、通知和幂等结果；制造其中任一步失败时全部不生效。
10. 退回要求原因，正式数据和正式版本不变；提交人收到通知，旧提交单保留，新一轮使用新 ID。
11. 提交后若管理员保存或导入改变任一正式记录，批准整单进入明确冲突，不能部分成功或静默覆盖。
12. 重复批准、浏览器回退重发以及两位复核员并发审批不会再次写正式数据，也不会重复生成有效审计或通知。
13. 批准后的黄色字段按现有 `DatasetSchema.complete` 统一计算；草稿和待复核值始终不计入正式完成率。

### 通知与审计

14. 未读数只统计当前用户；标记通知已读不移除仍待处理的复核单。
15. 通知详情链接经过业务权限校验；跨支行访问返回拒绝或无数据，不泄露摘要外内容。
16. 正式字段可从审计记录追溯提交人、批准人、提交单、旧值和新值；支行查询不包含其他支行记录。
17. 通知、日志、页面和测试数据均不包含真实账号、密码、业务表格或客户信息。

### 页面与兼容性

18. 核心流程使用服务端 HTML 和普通表单，关闭 JavaScript 仍可保存、预览、提交、批准和退回；所有 POST 校验会话及 CSRF。
19. 差异表格提供明确标题、字段表头、空状态、冲突摘要和错误回显；键盘可到达主要操作，焦点顺序与视觉顺序一致。
20. 1366 与 1920 宽度下操作按钮不被截断，长差异表保留横向滚动和可读换行；页面不引用在线字体、在线图标或现代浏览器独占组件。

# rc.5：截止日期最早明天

版本 `0.3.0-rc.5`，schema 仍为 6，不新增数据库迁移。

- 超级管理员与分行管理员新设或修改反馈截止日期时，必须选择北京时间今天之后的有效日期，即最早明天；今天和过去日期均不允许。
- 由保存事务中的服务端时钟校验，不依赖浏览器时钟、JavaScript 或原生日期控件。禁用脚本、旧 IE 和直接提交 HTTP 请求同样受限制。
- 校验失败返回 400，提示最早可选日期，不改变已有配置、版本、正式数据或审计记录。
- 已有日期不会因为时间流逝被删除或拒绝读取，正常计算倒计时和超期；可以延期至明天或之后，也可取消。即使重复保存相同日期，只要已是今天或过去也会被拒绝。
- 截止当日结束前有效、草稿／待复核不计完成、支行隔离等 rc.4 规则不变。本轮不自动修改任何用户设置。

验证包含两名管理员在真实 HTTP 请求中提交昨天／今天／明天，以及受控时钟下北京时间零点边界、无副作用拒绝、日期自然到期、重启保留、延期／取消、正式完成状态和授权导出。时间注入仅供 Java 测试构造使用，没有新增远程设置服务器日期的入口。

本地验证通过：`node tools/build.mjs --test --offline`、`node tests/install-smoke.mjs`。截止日期平台测试 45 项、HTTP 测试 24 项、展示与导出测试 13 项通过，同时完成其他模块回归。不使用 GitHub CI，麒麟／旧 IE 实机验证仍需现场完成。

# 智慧信管 rc.13：复核与导航交互修复

2026-09-23 用户要求在另一台 AI 的 rc.12 提交上修复首页按钮、分行角色清单、退回理由、整单操作和返回上一页。由当前维护人直接实施；不分配新的 A/B READY 任务，不启用云端 CI。

## 行为

- 首页和明细的“去复核”“查看历史修改记录”使用两个可辨识的按钮。只有支行复核员可处理待支行复核行、分行管理员可处理待分行终审行；分行管理员清单不显示“待支行复核”标签或错误的复核入口。
- 单行及批量退回先取得理由。正常脚本使用弹窗；无脚本或弹窗未写入时，服务端显示明确的原因填写页，空理由不会提交审批、更不会把用户丢进 400 错误页。实际审批仍沿用原有服务端授权、CSRF、事务和幂等校验。
- 多行复核区只保留紧凑的“全部通过／全部退回”按钮；逐行操作仍在表格第一列。
- 返回按钮打开同站 `document.referrer` 的准确 URL（含筛选参数），不再调用可能回到错误历史条目的 `history.back()`；缺少可信来源时保留页面原有安全后备链接。

## 验证和边界

执行完整本地离线构建测试、安装器模拟、差异检查，并新增退回原因后备页、角色入口、批量按钮和导航 DOM 回归。schema 仍为 10，无迁移；可按正常安装器从 rc.12 升级，保留业务库和旧包。实际 Win7 IE、麒麟设备和现场浏览器视觉效果仍需用户实机验收。

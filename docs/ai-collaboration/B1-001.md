## 必做功能

1. 操作员按机构、表种、来源期次选择可编辑正式记录，顶部统一“保存草稿”“提交”按钮，不为每个单元格放保存按钮。恢复本人草稿，显示版本与保存结果；他人包括管理员不能读取私人正文。
2. 草稿保存使用完整草稿差异集合和草稿版本；不能分页保存时意外丢掉其他页已保存的修改。只可修改 DatasetSchema 黄色字段，枚举用既有选项。
3. 提交时调用 previewDraft，显示服务端的记录、企业、期次、字段名、原值／新值与变更条数。确认 POST 仅传预览 ID 和稳定 requestId，不能重新传一份未经确认的内容。预览不创建待办。
4. 确认后显示不可变提交详情及状态；查看本人提交、待审、通过和退回。后续草稿编辑不能改变已提交快照。
5. 复核员查看本支行待办及整单差异，批准或填写必填原因退回。已读不等于审批，不能自审；多复核员处理同一单时正确提示已处理。
6. 退回后展示原因，恢复／修订草稿并关联旧单重新提交；新单保留历史链，不改旧单正文。
7. 分行管理员、支行管理员、复核员本人修改使用 previewDirect → confirm，无需其他人批准；超级管理员和操作员不能走该入口。
8. 展示身份变化、确认过期、草稿或正式行冲突、已有待审、缺少复核员、重复请求内容变化及整单失败；只展示授权范围内的冲突详情，不静默覆盖。
9. 草稿／待审／退回均不改变正式统计或导出；清空最后一个正式黄色值后未完成。禁止用 publishDirect 充当审批，禁止自建持久化。
10. 数据表长文本合理换行、保留横向滚动；服务端 HTML 和普通表单为核心，不依赖 fetch、Promise、在线字体、外部 CDN 或现代 JS 才能操作。

## 真实接口与接入约定

调用 `PlatformStore.workflow()`、`PlatformStore.notifications()`、已授权 `list/find`、DatasetSchema；完整签名与错误说明在 workflow-platform-api.md。身份只能来自真实会话，不能信任客户端角色或机构。

为避免双方修改 Main，提供默认包的 `src/workflow/WorkflowRoutes.java`（现有 AuthService／HttpSupport／PageLayout 也是默认包）。约定构造器 `WorkflowRoutes(PlatformStore store, String version)`，提供：

```java
boolean get(HttpExchange x, AuthService.Session session, Map<String,String> query) throws Exception;
boolean post(HttpExchange x, AuthService.Session session, Map<String,String> form) throws Exception;
```

只接管 `/workflow` 和 `/workflow/...`，匹配并响应返回 true，不匹配返回 false。不关闭 exchange，不自行创建或重置会话。A 的 Main 在有效登录、首次改密及本次安全确认后调用 GET，在会话检查、请求大小及 CSRF 通过后调用 POST。服务层仍重验授权。每请求创建页面对象，不把当前用户存入共享单例。A 注册 workflow.css、导航、通知跳转和测试执行入口。

请尽早创建 Draft PR，在任务回报列出具体 URL、方法、表单参数、测试类全名和命令。A 根据清单作公共接入小提交；不能最终只交无入口的页面，也不能为了自行接入修改 Main。暂可在工作流专用测试中建立隔离 HTTP harness，合并前仍须由 A/B 联调真实 Main 链路。

本任务优先的页面：草稿列表／编辑、差异预览、提交详情、我的提交、复核待办。通知中心及公共审计 UI 归 A1；B 仅提供本任务详情页和链接需求。现有三表原始展示归 B2，不在 B1 重写。

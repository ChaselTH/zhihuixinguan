## 实现结果

### 两级审核与逐行状态

- 增加行阶段 `READY / BRANCH_REVIEW / DIVISION_REVIEW / RETURNED / PUBLISHED / LEGACY_PUBLISHED`，提交单汇总状态分别表达待支行、待分行、部分处理、批准及退回；提交快照保持不变，决策逐行记录事件。
- 操作员确认提交后进入支行复核；支行复核只把明确选定的行送分行，不写正式业务值／版本。分行终审才在事务内发布正式值并生成审计／通知。支行管理员及复核员本人编辑也送分行，分行管理员直接确认是终审发布，超管保持只读。
- 支持行级批准／退回及部分处理、必填原因、终审后重开指定行；并发占用、阶段、行版本、幂等 requestId 和事务冲突均由服务端校验。
- 示例：`POST /workflow/review/approve` 需 `submissionId`、明确 `recordIds` 和 `requestId`；复核员只推进到分行待审，分行管理员才发布。`POST /workflow/review/reject` 同样限定所选行并要求原因；`POST /workflow/reopen` 由分行管理员二次确认指定记录。

### 角色读模型与完成状态

- 业务明细、行过滤和正式导出采用同一可见性规则：超级管理员／分行管理员可见全域；其余支行角色只能看本支行待处理行，待分行终审和正式完成行不会通过“全部”、筛选、直链、搜索或导出泄漏。
- 待支行复核及待分行终审优先显示；支行统计分母保留已隐藏记录。正式完成必须是有效发布且满足当前黄色列规则；草稿、两级审核在途和终审退回不计完成。终审缺必填项时不计完成并回到待补充范围。
- 页面动作文案区分“复核通过并提交分行”和“终审通过并发布”。支行管理员／复核员的页面说明也明确正式数据只由分行终审更新。

### 单入口识别与所选月份

- `/imports` 是唯一上传入口；解析每个上传文件中的实际工作表，按已有三类模板结构识别，允许只传单类、多文件／多表及原三子表工作簿；未知有数据工作表会报错，说明／空表可解释跳过。
- 上传表单强制选择 `YYYY-MM`；服务端校验并冻结到导入暂存任务，预览和确认沿用同一月份。所有新行按所选月归档，模板来源日期原样保留、不再决定月份。
- 有在途审批的导入覆盖会冲突阻断；预填黄色值进入待处理，不伪造成已审核完成。示例流程：`POST /imports` 多部分上传（`files` + `month`），返回一个暂存预览；以暂存任务 token 提交 `/imports/confirm`，不能在确认时改归档月份。

# 智慧信管 0.3.0-rc.7：离线安装与升级

本包为完整流程联调测试版，应用版本 0.3.0-rc.7、数据库 schema 7。面向麒麟断网安装及局域网访问；真实麒麟／CPU、Win7 实际 IE 和正式安全验收仍须现场完成。

## 使用哪个目录

U 盘中的 `zhihui-xinguan-offline-0.3.0-rc.7-kylin` 是本次安装目录，含 `install.sh`、`payload`、两种架构 Java、模板及校验清单。无需联网，不用额外安装 Java、数据库或 Node。旧版目录保留，但本次请使用 rc.7。

包的 `SOURCE_COMMIT` 记录对应源码提交；本次安装包不包含本机的业务数据库。若另外保存了源码目录，请核对其 SOURCE_COMMIT，旧 rc.2 源码不等于本次版本。

## 更新已有测试安装

1. 在麒麟旧服务窗口按 Ctrl+C，确认停止。不要一边运行一边升级，也不需要先卸载。
2. 把 U 盘上的完整 rc.7 安装目录复制到麒麟本地；不要只复制 install.sh，必须保留 payload 与 SHA256SUMS。
3. 在复制后的目录打开终端执行：

```bash
bash install.sh
cd "$HOME/ZhihuiXinguan-PR0"
./start.sh
```

默认安装目录继续沿用 `ZhihuiXinguan-PR0`，以保留原有数据。如以前装在其他位置，必须指定原 start.sh 所在的绝对目录：

```bash
INSTALL_DIR="/原安装目录的绝对路径" bash install.sh
```

不要原样使用上面的占位路径，也不要把 U 盘安装包目录误当成旧程序安装目录。不确定时先核对原服务的位置。

启动时询问端口，直接回车使用 2874；被占用时选择其他空闲端口。服务前台运行，Ctrl+C 关闭；另开终端进入安装目录执行 `./start.sh status` 查询状态。浏览器访问 `http://麒麟电脑IP:所选端口/`，网页显示 `V0.3.0-rc.7`，`/health` 返回 `SCHEMA=7`。更新后重新登录。

## 账号、设置和数据保留

- 升级沿用工作电脑上的账号、密码、机构、正式记录、填写内容、草稿、提交及审计记录，也保留已经设置的反馈截止日期。本包不会导入或覆盖开发电脑的测试数据库。
- 私人测试包可附 `payload/bootstrap.local.properties`，只供首次空库初始化；升级时优先保留原安装的初始化配置，已有账号不重置。请按凭据保管整个私人包，不公开上传、发布或转发。
- 通用源码没有默认账号密码。若使用不含私人初始化配置的通用包，首次空库运行需参照 bootstrap.example.properties 在本机填写。
- 安装器先校验文件，把旧 data 复制到暂存目录验证迁移，成功后才替换；旧目录完整保存在安装父目录的 `.zhihui-xinguan-backup-时间-编号`，不自动删除。
- 失败立即停止，保留原版、错误和备份。不要删除数据库或未完成迁移标记来绕过错误。
- rc.7 新增 V007 正式数据删除标记，V001～V006 不改，升级不自动删除数据。schema 7 不可交给 rc.6 或更早程序使用。升级后有新写入时，不能直接覆盖旧备份回退，应先保全新数据。
- 备份须保留完整 data 目录，特别是 `data/platform/initial-password.key` 及 `.bak`，不能只复制 records.mv.db。主密钥和副本同时丢失而库内仍有临时密码密文时会拒绝启动。

## 本次重点测试

1. 核对升级前后的账号、历史月份、记录数、已填反馈、待办、导出及截止日期。
2. 一个入口上传含负面闭环、多重预警、交叉违约的三工作表文件；查看新增／重复／更新汇总，选择保留或覆盖后一次确认。覆盖时上传空白也会清空相应旧填写值。
3. 上传不再填写所属月份和补充期次。多重预警／负面闭环按原来源期次；交叉违约按 L 列“违约首次出现时间”分月，缺失或无效日期整批报错，不用文件名覆盖该日期。
4. 三类清单均在风险预警，首页统计卡可进入明细；每家支行显示三项填报进度，分行／超级管理员可批量导出进度。明细支持返回、分页（10／20／50 条）、上下联动横向滚动条。
5. 超级／分行管理员在首页“本期反馈时间 → 设置反馈截止日期”按清单和来源期次设置；没有数据的期次不显示。新设／修改只能选北京时间今天之后的日期（最早明天），今天或过去日期应报错。
6. 截止日当天结束前有效，次日北京时间零点起正式未完成标红为“超期反馈”；黄色填写列不变。已有日期到期仍保留，可延期或取消。首页剩余时间刷新后更新。
7. 草稿／待复核不计正式完成；正式黄色字段任意一个有内容即完成并显示浅绿色。支行只看本支行，操作员提交需复核；通过后才进入统计和导出。
8. 人员管理列表有红色“删除人员”按钮，需核对姓名、认证号及机构后确认；删除为停用账号、撤销会话，保留历史记录和认证号，可通过修改人员状态恢复。只能操作权限范围内的下级，未交接职责仍阻止停用。
9. 操作记录：支行看本支行，分行看全部支行但不看超管操作。超管按条件查询后可预览并清理全部分页的匹配记录；明细不可在网页恢复，另留清理摘要。开发和升级均不自动清理记录。
10. 数据更新的“按月份删除数据”只对分行管理员开放；三类清单本月全部支行一并预览，有待复核单拒绝删除。已删除行退出正式展示／统计／导出，历史快照保留；旧草稿和旧导入预览不能复活数据。跨月期次整条删除会在确认页警告。
11. 以工作电脑实际 IE 检查登录、选择框、导入、保存、审批、滚动和下载；不要把现代浏览器通过当作旧 IE 已验收。

无风险按钮未实现，安全提示仍待正式文案，其他行内数据模板待提供。HTTP 不加密，仅在获准的隔离内网联调；正式推广前需落实行内传输保护。

# 智慧信管 0.3.0-rc.2：离线安装与升级

本版已合并 A1、B1、A2、B2 及 FEEDBACK-001（PR #10），schema 5，是完整流程联调测试版。并不表示已通过当前麒麟／CPU、Win7 实际 IE 或正式安全验收。

## U 盘里两个目录的用途

- `zhihui-xinguan-offline-0.3.0-rc.2-kylin`：在麒麟安装，含 install.sh、离线应用、x86_64／aarch64 Java、模板及校验清单。无需联网、额外安装 Java／数据库／Node。
- `zhihui-xinguan-source-0.3.0-rc.2`：同一提交的源码、技术文档、测试、构建与打包脚本，以及已校验的 vendor/dependencies。用于备份和继续开发，不是点击即用安装目录；没有 .git 历史、真实数据或初始化密码。

旧 U 盘目录保留，不自动删除。两个目录的 SOURCE_COMMIT 必须相同。

## 更新以前的测试安装

1. 在旧服务启动窗口按 Ctrl+C，确认停止。不要一边运行一边升级。
2. 把新离线安装目录完整复制到麒麟本地，保留 payload 与 SHA256SUMS，不要只复制 install.sh。私人包中的初始化配置按凭据保管，不上传到公共仓库或群聊。
3. 在复制的目录打开终端执行：

```bash
bash install.sh
cd "$HOME/ZhihuiXinguan-PR0"
./start.sh
```

为了升级原有测试库，默认安装目录仍沿用 `ZhihuiXinguan-PR0`，不是重新装一个空库。若以前明确安装在别处，应对**原安装目录**执行：

```bash
INSTALL_DIR="/原来的绝对安装目录" bash install.sh
```

不要把示例路径原样使用；不确定旧安装位置时先核对旧 start.sh 所在目录。默认端口 2874，启动时可以输入其他未占用端口。前台运行，Ctrl+C 关闭；另开终端进入安装目录执行 `./start.sh status` 查询运行状态。浏览器访问 `http://麒麟电脑IP:所选端口/`，网页显示 V0.3.0-rc.2；`/health` 应显示 `SCHEMA=5`。无需先卸载 rc.1。

## 账号与数据保护

- 已有账号、密码、机构、数据、填写和工作流历史都保留，不因新包重新初始化或重置密码。
- 首次空库安装才使用本地 `bootstrap.local.properties`；如果私人包未附带它，参照 bootstrap.example.properties 在安装目录本地填写。通用源码没有默认账号密码。
- 只有分行管理员上传；超级管理员业务只读。操作员保存草稿／提交，由本支行复核员通过才写正式数据；分行管理员、支行管理员、复核员直接修改也先确认差异。
- 安装器先校验、复制旧数据到暂存区，再验证迁移；成功才替换。旧目录完整保存在安装父目录下 `.zhihui-xinguan-backup-时间-编号`，不自动删除。
- 失败立即停止，保留原目录、备份和错误信息，不删除数据文件或迁移失败标记。新增 V005 后 schema 5 不可直接用旧 rc.1（schema 4）或更早程序运行；升级后已有新写入时不能直接用旧备份覆盖，应先联系维护人保全新数据。
- 临时密码的加密密钥及备份位于 `data/platform/initial-password.key` 与 `.bak`，必须与数据库一起备份／恢复。升级器复制整个旧 data 目录；不要仅备份 records.mv.db。主密钥和备份同时丢失且仍有密文时会拒绝启动，请保全目录并联系维护人，勿删除数据来绕过检查。

## 首轮验收

先用已有账号登录，核对升级前后人员、机构、历史月份、条数、已填反馈和导出。再用虚构或合规脱敏数据测试统一三表导入、保存草稿、差异确认、提交、复核通过／退回、通知、审计和正式完成率。核对支行不能访问其他支行，草稿／待审内容不进入正式导出。用工作电脑实际 IE 版本检查选择框、提交和下载。

本版重点检查：申请分行／支行的选中效果与目标角色；重复申请和缺上级管理员提示；初始密码授权再次查看、首次改密后不可查看；人员逻辑删除和责任保护；点击通知后的未读气泡；一个上传入口、统一模板与汇总预览。

跨月批量导入时，每个文件需包含三张子表，并带明确文件名月份／期次；公共月份可留空。行内有明确时间顺序的记录按行分期，交叉违约不使用首次违约日充当数据月份。公共月份与文件名或补充期次冲突会整批报错，不要为了通过校验随意改月份。一个没有可识别月份的文件可单独填写公共月份上传。

当前仍没有正式反馈截止字段，不显示超时红色，不实现无风险按钮。安全提示仍为占位，其他行内模板未提供。HTTP 未加密，只能在获准的隔离内网测试；正式推广前需确认行内传输保护。

## 源码的离线构建

开发电脑需自行具备 JDK 17+、Node 22+（不是麒麟运行所需）。源码目录自带锁定 JAR 缓存：

```text
node tools/build.mjs --test --offline
node tests/install-smoke.mjs
```

Windows 安装模拟另需 Git for Windows 的 Bash。源码快照不带 Git 历史，普通构建可执行；再次发布打包需先初始化开发仓库并提交，以生成可追溯 SOURCE_COMMIT。GitHub CI 已按用户要求停用，后续不自动恢复。

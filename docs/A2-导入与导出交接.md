# A2：导入与授权导出交接

2026-09-16，版本 `0.3.0-a2.1`，schema **4**。分支 `codex/v0.3-import`，基线为 A1/B1 已合并的 main：`ff8f65eda54bf2728a09d9f7b1ad4ae4fcacd32d`。本轮提交独立 PR 等待评审，不自动合并、放行 B2 或制作私人安装包。

## 1. 已实现的操作流程

1. 分行管理员登录并完成安全确认，在“数据更新”选择负面闭环、多重预警、交叉违约三个入口之一。同一文件有三个子表时，分别从三个入口读取对应子表；一个任务只处理一个表种。
2. 一次选择 1～10 个同类文件。旧 IE 保留两个独立文件选择框；不要求多选 API、现代 JavaScript、联网字体或组件。
3. 先校验全部文件。错误页列出文件、工作表、Excel 行号、列字母及原因；每文件最多显示前 100 个错误。任一文件错误，整批不创建正式数据或待确认任务。
4. 校验成功创建本人导入任务；预览按每页 25 条展示来源位置、系统原填报值、上传值、近似来源候选及待复核影响。此时正式统计、导出均不改变。
5. 每条可选“保留已有填写，仅补空白”“覆盖为上传值（含清空）”“跳过”；也可统一设置整批。翻页前保存本页选择，保存只更新暂存任务。确认整批使用已保存选择，不发送客户端业务值作为正式内容。
6. 存在覆盖选择时必须额外确认空白也会清空旧填报；存在未跳过的来源修订候选时必须确认按新记录新增。全跳过任务不能确认，可直接取消。
7. 确认时重验身份、选择版本、有效期及该表种正式数据基线。正式行、导入批次、逐条决定、任务状态、公共审计在同一个事务提交；任一失败整批回滚。
8. 返回新增、重复、保留已有填写条数。可从“我的导入任务”继续查看；同一确认请求重试返回原结果，改变决定后重放被拒绝。

## 2. 数据口径与保护边界

- 只有 `DIVISION_ADMIN` 有上传、模板、暂存和确认权限，超级管理员不例外。暂存内容只允许创建人访问，其他分行管理员也不能查看或确认。已经正式导入的业务仍按原角色范围可见，未另建身份或审计系统。
- 默认保留旧非空填报，仅用上传值补旧空白。显式覆盖包括清空。完全无变化的重复行不递增正式行版本，也不会无故使审批失效。
- 重复指纹沿用公共契约：表种＋规范期次＋机构＋**全部非填报来源列（含序号）**，排除黄色列、文件名和技术时间。相同客户不是完全重复的充分条件。
- 同批相同来源且值相同折叠；相同来源但填报冲突整批拒绝，提示两处来源位置。与系统同客户、同机构、同期但来源不同的行只提示候选，不自动覆盖或模糊合并。
- 更新保留原稳定记录 ID。不会删除其他月份、其他模块或本批未出现的历史行；这不是“整期替换删除”功能。
- 导入更改待复核记录后，原草稿、冻结提交单均保留；后续审批的预期版本检查将阻止覆盖已更新正式值，不自动批准或重写提交单。
- 九支行及黄色填报列仍来自 `Organizations`、`DatasetSchema`。任意黄色单元格非空即完成（`0`、`否`也算）；不把来源列计入完成率，不新增无风险或反馈截止字段。
- 文本客户编码保留前导零；数值编码按已存显示格式读取，16 位及以上数值编码（包括数值公式缓存）拒绝，要求核对原始文本，不能修复 Excel 已经丢失的精度。
- 公式仅读取文件已保存缓存，不运行公式、外部链接或宏；缺少缓存／错误缓存拒绝。公式空字符串缓存是有效空值，不等于无缓存。所有导出单元格按文本写入，以 `=` 开头的反馈也不会成为可执行公式。

## 3. 持久化、限制与恢复

新增 `V004__import_jobs.sql`：`import_jobs` 保存拥有者、身份版本、表种、状态、选择版本、有效期、基线和结果；`import_job_rows` 保存冻结来源、旧值、位置、选择及影响摘要。V001～V003 未改写。

- 任务状态：`PREVIEW → COMMITTED / CANCELLED / EXPIRED`。确认成功后不可再改选择。
- 待确认期为创建起 **30 分钟**，不因翻页或重新登录延长；同身份版本下重新登录、服务重启可恢复。改密、角色／机构等身份版本变化后，旧任务拒绝访问，需要重新上传。
- 取消立即清除暂存行；过期任务在创建任务或查询任务列表时清理行内容，保留状态摘要；即使尚未清理，过期确认也会被拒绝。已导入历史与选择保留，保留期限策略由后续正式运维确定。
- 每人最多 3 个、全站最多 20 个未过期待确认任务。单文件 20 MB、HTTP 整批 50 MB、一批最多 20000 行、单元格 10000 字、批次单元格合计 800 万字。原上传文件只在内存解析，不写入原始业务文件缓存目录。
- 正式基线是**整表种**的稳定 ID／行版本摘要。预览期间即使另一机构同表种数据变化，也需取消后重传；这是初版保守防覆盖策略，不能跳过检查强行确认。
- 新库按 V001～V004 顺序创建；旧 V1/V2/V3 库逐步升级。迁移中断继续采用现有 fail-closed 机制，必须按安装恢复流程处理，不能直接删除迁移失败标记或降版本号。
- schema 4 数据库不能直接交给 schema 3 程序运行；回退应停止服务、保全新数据并恢复成套旧程序／旧库备份。已有新业务写入时不得直接覆盖回旧快照。

## 4. 实际 HTTP 接口

全部业务接口经过 Main 的真实会话、身份有效性、首次改密及安全提示门禁；POST 必须提供当前会话 CSRF。服务端仅使用会话身份，不信任表单角色和机构。

| 方法及路径 | 输入／结果 |
| --- | --- |
| `GET /imports` | 三个上传入口、模板及本人任务导航 |
| `POST /imports/upload/{negative,multi,cross}` | multipart：`csrf`、`files`、`month`、`period`；200 预览，400 详细错误；空白模板 303 提示、不创建任务 |
| `GET /imports/jobs?offset=0` | 本人任务，每页 25 条 |
| `GET /imports/preview?token=…&offset=0` | 本人任务及已保存逐条决定，终态只读 |
| `POST /imports/choices` | `csrf/token/revision/offset`；`choice_1=PRESERVE` 等逐条值，或单独传 `allChoice=PRESERVE/OVERWRITE/SKIP`；成功 303 |
| `POST /imports/confirm` | `csrf/token/revision/mode=saved`；可选 `confirmOverwrite=yes`、`confirmSimilar=yes`；成功或相同重试 303 |
| `POST /imports/cancel` | `csrf/token/revision`；成功 303，重复取消安全返回 |
| `GET /template?dataset=…` | 对应表头版本 v1，新增“模板说明”Sheet，原数据 Sheet 结构／黄色列不变 |
| `GET /export?dataset=…` | 保留现有 `scope/month/year/quarter/start/end/branch/q` 参数，授权正式记录生成单个 Sheet 的 XLSX |

统一错误：无权限／非本人 403，输入／格式不合法 400，过期／基线或选择版本冲突／已完成后改决定重放 409，HTTP 请求过大 413，事务故障 500。错误页不回显内部 SQL 或原始异常堆栈。确认兼容旧客户端的 `mode=preserve/overwrite`（缺省 revision=1）；新页面统一使用显式 revision 和 `mode=saved`。

## 5. Java API 与调用示例

`PlatformStore.importing()` 返回 `xinguan.platform.ImportPlatform`，底层方法实际读写 H2，不是空接口：

```java
ImportPlatform imports = store.importing();
ImportPlatform.Job job = imports.stage(actor, "multi", sources, skippedExamples);
ImportPlatform.Preview preview = imports.preview(actor, job.id(), 0, 25);
job = imports.choices(actor, job.id(), job.revision(),
    Map.of(1, ImportPlatform.Choice.PRESERVE, 2, ImportPlatform.Choice.SKIP), null);
PlatformStore.ImportOutcome result = imports.confirm(
    actor, job.id(), job.revision(), "saved", false, false);
// 同参数重试返回同一 batchId，不增加正式记录。
```

- `stage(ActorContext,String,List<SourceRow>,int) → Job`
- `jobs(ActorContext,int offset,int limit) → List<Job>`
- `preview(ActorContext,String id,int offset,int limit) → Preview`
- `choices(ActorContext,String id,long revision,Map<Integer,Choice>,Choice all) → Job`
- `cancel(ActorContext,String id,long revision) → Job`
- `confirm(ActorContext,String id,long revision,String mode,boolean allowClear,boolean allowSimilar) → ImportOutcome`

`SourceRow(BusinessRecord record,String sheet,int row)` 的 row 为 Excel 1-based 行；`Item` 含 number/source/previous/similar/pending/choice；`Job` 含 id/dataset/state/revision/createdAt/expiresAt/count/examples/repeated/resultId。分页 limit 1～30，offset 0～20000。输入非法抛 `IllegalArgumentException`，越权抛 `SecurityException`，冲突抛 `ConcurrentModificationException`，底层失败抛 `IllegalStateException`；均回滚。

`AuthorizedExportService.export(ActorContext,Map<String,String>)` 统一 HTTP 导出：从授权正式仓库和现有 `RangeSelection` / `DashboardData.filtered` 取数据，返回 `bytes/filename/count`。只导出所选表种，不附带隐藏 Sheet、其他支行、草稿或待审内容。底层 ExcelExporter 只负责编码，不可作为新 HTTP 路由的授权替代。

# 智慧信管 V0.3.0-rc.13

本版在 rc.12 两级审核基础上修复复核与导航交互，数据库 schema 仍为 10。麒麟安装和运行完全离线，包内含 Linux x86_64／aarch64 Java，不需要另装数据库或 Node。网页采用 Java 服务端 HTML 和本地静态资源；真实麒麟、Win7 旧 IE 仍需现场验收。

## 本版变更

- 通知按机构和人员分开：操作员只看到自己提交及被退回的通知，复核员只看到与自己复核过和之后被退回的通知；终审退回和终审重开只通知对应的人和原提交人，不再全支行广播。
- 分行管理员退回某行后，先回到对应支行的复核员待复核清单；复核员可以退回给操作员重改，也可以自己修改后重新提交分行。
- 首页和清单中待复核（待支行复核／待分行终审）的行优先排到表的最上面。
- 能复核的人（支行复核员、分行管理员）在待处理清单里只保留一个“去复核”入口，不再同时出现“查看提交回执”。
- 点击“去复核”后的界面是整行表格，第一列为“操作”；退回时弹窗填写原因，若脚本失效则进入独立原因填写页，不会因空原因直接报 400。多行单据使用紧凑的“全部通过／全部退回”按钮。
- 首页和明细的“去复核”与“查看历史修改记录”分别显示为按钮；分行管理员不再看到“待支行复核”标签或无权处理的入口。返回上一页直接打开同站来源页面，保留原筛选条件。
- 分行管理员在三个清单详情的第一列新增“查看历史修改记录”，可以看到该行的所有填报、复核、退回、发布记录及操作人姓名和角色。
- 删除行状态里无意义的“历史正式数据”标签。
- 登录后的数据安全提示改为正式内容（保密、最小授权、禁止外传、操作留痕、离岗锁屏等）。

## 本版功能

- 操作员保存私人草稿、预览差异并确认提交后，先由支行复核员审核，再由分行管理员终审；只有终审才更新正式内容。支行管理员／复核员本人修改经确认后送分行终审；分行管理员本人修改经明确确认直接发布，超级管理员业务只读。
- 支行角色仅看本支行待处理业务；已交分行或正式完成行不能通过“全部”、旧明细链接或导出读取。分行／超级管理员保留全表范围；精简流程回执和授权审计仍可查询。
- 首页分为统计与三类待处理清单。复核员优先处理操作员提交，分行管理员优先处理支行上送；分行可退回在途任务或重开完成行，原正式值保留。
- 部分退回按行恢复，私人草稿不共享。原内容正确无需改字时，可明确选择“核对后原值重提”，生成新审批链，不伪造正式值修改。
- 数据更新仍是一个入口，按表头自动识别单表、一至三类工作表或多个文件。必须选择所属月份，本批统一归入所选月份；原“时间顺序／违约首次出现时间”保留为来源字段，不再决定新上传批次。不自动重分历史月份。
- 导入黄色列预填内容属于候选，经独立支行复核员确认后再由分行终审；唯一分行管理员可终审自己的上传候选，普通业务提交本人审核限制不变。
- 两级在途任务均阻止覆盖和按月删除；错误表头、未知非空页、版本冲突等明确报错，整批失败不部分生效。

人员管理、权限申请、安全确认、通知自动已读、支行审计隔离、必填设置、截止日期、分页与双向滚动、授权 Excel 导出均保留。未填齐必填项仍可提交和审核，但终审后仍不计完成，并回到支行待处理范围。草稿及待审候选不进入正式统计和导出。

只有分行管理员上传；超级／分行管理员可导出整体进度及设置截止日期，新日期须晚于北京时间今天。当前安全提示文案上线前仍须行内审定；无风险按钮未实现，其他行内数据模板待补充。

## 安装、启动和更新

使用完整目录 `zhihui-xinguan-offline-0.3.0-rc.13-kylin`。先在工作电脑旧服务窗口 Ctrl+C 停止，将完整包复制到麒麟本地，再执行：

```bash
bash install.sh
cd "$HOME/ZhihuiXinguan-PR0"
./start.sh
```

无需卸载。默认目标沿用原 ZhihuiXinguan-PR0；如果原来装在其他目录，必须通过 INSTALL_DIR 指定原安装绝对路径。不要把 U 盘包目录当成原安装目录。详见包同级《安装测试说明.md》。

启动时询问端口，回车为 2874；Ctrl+C 关闭，`./start.sh status` 查询状态。网页应显示 0.3.0-rc.13，/health 应返回 SCHEMA=10。

## 数据保留和升级边界

安装器先校验，在暂存副本上验证迁移，成功后替换并保留完整旧版备份。原账号、密码、业务、草稿、审核历史、审计、必填规则和截止日期保留；本包不带开发电脑业务数据库。

原 rc.10 发布包的 schema 8 可升级；新增 V009/V010，V001～V008 不改。旧正式内容保持原口径，旧待审进入两级审核，不伪造历史分行批准。同一行存在多份旧待审时先明确退回重复任务，再批准剩余任务。

若曾运行未修复 PR #12 并迁移到 schema 10，本版会因迁移校验不符拒绝启动。保全该测试库，从已验证的 schema 8 升级前备份在隔离目录重做；没有备份请联系维护人，不改 checksum、不清库、不强行降级。

schema 10 不能用旧程序直接运行。回退须恢复升级前完整备份，并先保全升级后数据。备份须含完整 data 目录、platform/initial-password.key 及其 .bak，不可只复制 records.mv.db。

私人包可附初始化配置，仅首次空库读取，升级不重置已有账号。配置和整个私人包须按凭据保管，不上传公共仓库；通用源码没有默认密码。

## 开发验证与限制

开发需 JDK 17+、Node 22+；Windows 安装模拟另需 Git for Windows Bash。麒麟安装运行不需要这些开发工具。

```text
node tools/build.mjs --test --offline
node tests/install-smoke.mjs
```

完整测试需要锁定依赖缓存和本地 Git 旧提交对象，以运行真实旧库升级回归。Git 当前提交导出的源码快照没有历史，支持普通离线构建，但不能独立完成历史升级测试；不要为此复制整个工作目录、真实数据或私人配置。

不使用 GitHub／云端 CI。本地 HTTP、DOM 和安装器模拟不等于麒麟／实际 IE 实测。当前 HTTP 未加密，仅用于获准隔离内网联调；正式推广前须落实行内传输保护。网页不加载外网资源，不调用大模型。
